# AI PM Capability 与工具资产治理

本文件供仓库维护者使用，不是运行时 Skill 指令。正式触发与专业方法仍以 [Skill Kernel](../skills/ai-product-development/SKILL.md)及各 Capability 的 `SKILL.md` 为准；本文件不创建新的 Lifecycle、Gate 或状态机。

## 盘点节奏与证据口径

在每个主要 Skill 版本收口时盘点一次；真实项目持续使用期间每季度至少复核一次。仅做只读盘点，不自动修改或退役能力。每项记录：适用 Skill 文件清单/版本、真实任务中的触发与不触发机会、实际读取的入口/方法文件、误触发与漏触发原始 trace、输入/输出 token 或可用的耗时、[产出 Rubric](../tests/ai-product-development/phase5/real-work-rubric.md)、与相邻能力的决策/输出重叠、人工 owner 及下一步。

判断标签仅为维护决策：`保留`、`收窄触发/内容`、`合并候选`、`退役候选`、`证据不足`。某能力未出现在少量测试里，不等于低使用率。只有在有足够实际任务机会的观察期内仍长期不用，才列低使用率候选；持续误触发须有完整 trace 并排除测试器误判；合并须证明相同 gap、待解锁决策与输出合同重复，且合并后不损害触发精准性。删除/合并前检查入口、生命周期引用、模板、示例、历史报告和可恢复路径，保留决定依据。一次失误先做定点诊断，不为治理指标制造新的模型采样。

## 外部工具接入门槛

当前仓库没有具体 MCP/业务系统适配器；本地 project runtime CLI 和只读测试 runner 不构成外部业务接入。因此本轮不创建虚构 adapter、权限表或通用重试服务。若未来某项目明确要求接入某个外部系统，先在该适配器旁记录并审阅：

- 工具名、用途、输入/输出参数及校验；敏感数据最小化和权限范围；
- 读、写、发送、发布等副作用及逐项授权边界；目标系统、环境和 owner；
- 超时、重试上限、幂等键或去重方式；无法安全重试时的停止条件；
- 错误/超时/部分成功的可见状态、审计证据、人工确认与恢复/补偿步骤；
- 能力边界与产品 Gate 的关系：工具调用成功不自动等于产品决策或发布通过。

这些字段在**具体适配器**落地时成为其失败合同；缺任一影响安全执行的字段则阻塞该接入，不用更多提示词掩盖实现空缺。外部写入或通知仍须遵守用户对当前任务的授权。

## Trace 留存

当前版本的 PASS 仅在完整 Skill 清单与原始成功 trace 匹配时有效。采纳的 prompt、trace、stderr、metadata、结果及透明重判文件应相互可追溯；基础设施失败与合同失败不改写为 PASS。未采纳且无 manifest/报告引用的临时采样，在记录原因与精确目录后以可恢复方式清理；被报告引用的失败证据若确需移除，须先保证报告不出现失效链接，并保留失败原因。不要用批量清理代替版本适用性核验。
