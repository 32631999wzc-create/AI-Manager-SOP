# AI-Manager-SOP 使用边界

本 Skill 当前定位为**本地单用户 AI 产品开发 Beta**：帮助 PM 按交付目标、当前委托、已有资产与证据，选择必要的生命周期工作、专业 Capability 和可执行任务；不代替事实核验、责任人审批或生产系统控制。

## 适合

- 从模糊机会出发，形成有证据边界的产品定义、AI 可行性判断、评测设计和下一步计划。
- 接手已有 PRD、代码、数据或评测资产，识别真实缺口；对仍有效的工作选择 `REUSE`，对存疑资产选择 `VERIFY`。
- 处理局部需求变化、坏例或生产质量信号，追溯 Evidence → Decision → 受影响任务，给出最小 Replan。
- 单次审阅或明确要求的本地跨会话推进；持久状态只保存在受测产品仓库的 `.ai-product/`。

## 不适合直接承担

- 在没有授权与人工审批的情况下改动线上系统、自动发布、自动处理高影响个案或代表组织作最终合规判断。
- 把少量样本、模型自述或静态链接检查当作用户需求成立、模型质量达标或 Gate 已通过的证明。
- 默认建设多人实时协作、云端状态、组织级组合管理、财务/采购/法务流程或企业级基础设施；这些需要独立的明确委托。

## 必须由责任人确认

交付目标和 Assignment Scope；用户价值与优先级取舍；数据使用权、隐私和安全约束；可接受的质量/风险阈值；重大决策的采用或重开；Build/Release Gate 及任何对外或生产动作。Skill 可准备证据、方案和待确认问题，不能把未回答的问题伪装成默认批准。

## 结论依赖证据质量

用户研究取决于样本代表性与访谈真实性；AI 可行性和评测取决于数据许可、覆盖、标注、基线及 bad cases；生产结论取决于版本、时间窗、监控口径与事件链。来源缺失、过期、冲突或未经验证时，应保留假设、说明不确定性，并按影响范围选择 `BLOCKED`、`HUMAN_CONFIRM`、`VERIFY` 或补证据，不宣称确定结论。

## LIGHT 与实验性边界

`LIGHT` 是 Execution Profile 的**节点工作深度**，不是对 16 个 Capability 的统一质量评级。默认矩阵中，Prototype 的 Cognition、Solution Design、Validation & Iteration、Retrospective 可为 LIGHT；Demo 的 Release & Operation 可为 LIGHT；Retrospective 在各交付目标均默认为 LIGHT。实际深度仍受风险、依赖与委托范围抬升，LIGHT 不豁免必要 Gate。

16 个 Professional Capability 已有路由与合同，但不能据此宣称每个专业方法在真实企业场景都已逐项验证。跨域组合、生产学习闭环与高风险发布判断应视为**需要现场证据和人工审查的能力**；当前验证只支持代表边界和少量端到端任务，不支持“完美运行”或“100% 稳定”的承诺。
