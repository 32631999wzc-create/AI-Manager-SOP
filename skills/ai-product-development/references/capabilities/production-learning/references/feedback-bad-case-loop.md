# Feedback and Bad-case Loop

## Use

当生产反馈、纠正行为、工单或抽样审查需要转成可验证产品学习时读取。

## Intake and Triage

1. 建立 feedback taxonomy：偏好、任务失败、事实/推理错误、控制/理解、性能、权限/隐私、安全事件、申诉和功能请求。
2. 每项关联用户/任务切片、环境、产品/模型版本、输入输出引用、任务结果、严重度、可复现性和数据授权；不收集无用途原始日志。
3. 区分主动反馈、行为代理和抽样审查。thumbs up/down、纠正与支持工单均有选择偏差，不能单独视为真值。
4. 去重聚类但保留高影响单例；按伤害/严重度、频率、趋势、可检测性和战略相关性排序。
5. 对确认 bad case 形成 EvidenceRecord，路由到 Evaluation/Regression、Human-AI、Risk、PRD 或运营修复；每项有 owner、状态和回传结果。

## Close the Loop

修复后关联代码/配置/产品版本、定向与全量回归、rollout 和生产验证。未修复项保留原因、缓解措施和重开条件，不以“已查看”关闭。

## Completion

反馈能追踪到分诊、证据、决定、修复、回归和发布；选择偏差与敏感数据得到处理；重复问题和高影响单例都不会在汇总中消失。
